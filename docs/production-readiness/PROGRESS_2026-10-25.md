## Verification (this run)
See `TEST_RESULTS.md` for the dated numbers. New tests: backend `avatars`, `homework`, `chat-inbox`, `otp-login`, two bus tests; frontend `e2e/new-features.spec.js` and updates to `landing`, `auth`.

## Not verified, and why
- **Real SMS to a phone**: needs a provider account and, in India, DLT registration of the sender and template. SMS runs in test mode (the code appears in the server console).
- **Real email through Gmail, SES, Resend or Brevo**: needs credentials entered in the owner console (Integrations).
- **Mapbox road routing**: needs `MAPBOX_ACCESS_TOKEN`; without it an OSRM service is used (the public demo server is for trying only).
- **Real phones for the bus**: the driver app was exercised with the simulator, not a moving vehicle.
- Firefox, Safari, Edge and screen readers were not run against the new screens.
- Chat is polling-based (3 s), not push.

## Follow-up the same evening
- **Learning AI** did not answer on the local demo because that demo backend had been started with `ASSISTANT_AI=off` (which switches every model call off). Started without it, it answers (checked: a streamed answer to a student question). Never start the demo for real use with that flag.
- **Rings**: the circle shows a rounded number (95%) so it never overflows; the exact figure (94.9%) stays in the accessible name and in the page text.
- **Headers**: every screen's header now carries the screen's own icon, the title and a subtitle (the home screens show today's date); `usePageIcon` takes the icon from the portal navigation.
- **School office**: a read-only Homework screen (`/admin/homework`) lists every teacher's homework and who has finished it.
- Decided not to build: OTP on the demo-request form (it would add friction to leads), rings on the teacher home (it has no percentage to show), a redesign of the driver's own screen (needs a real vehicle to judge).
- Tests: layout, dashboard, parent-dashboard and new-feature suites pass against the final code.
